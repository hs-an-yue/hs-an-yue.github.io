第2节 数据库表管理

2.1 数据结构(常用)

分类 MySQL PostgreSQL 差异说明 & 业务建议
整型 tinyint / smallint / int / bigint smallint / int / bigint 取值范围基本一致 & 主键推荐两者都用bigint
高精度小数 decimal(p,s) numeric(p,s) 等价，无精度丢失；GPS 坐标、金额优先选用
浮点数 float / double real / double precision 两者都存在精度丢失
字符串 varchar(n) / char(n) / longtext text（推荐，不限长） / varchar(n) / char(n) PG 中 text 与 varchar 性能相同，推荐 text；MySQL 大文本用 longtext 等，性能偏弱
时间类型 datetime（无时区） / timestamp（有 2038 上限） / date / time timestamp（无时区） / timestamptz（带时区） / date / time PG 优先 timestamptz；MySQL 业务时间推荐 datetime
布尔 tinyint(1)（伪布尔，约定 0/1） boolean（原生，true/false/null） MySQL 布尔底层是数字，容易产生判断异常；PG 是原生布尔
JSON json json（文本）jsonb（二进制，支持 GIN 索引） PG jsonb 能力强，支持包含、键值索引；MySQL JSON 索引能力弱
数组 无原生数组 原生支持 bigint[]、text[] MySQL 只能逗号分隔字符串（不可索引）场景：点位关联多张图片 ID，PG 数组更便捷

其他空间地理信息的数据类型，请查看官网。

第3节 表级导入导出(COPY / \copy)

单表数据进出最常用的就是 CSV。PG 原生的 COPY 命令,比逐条 INSERT 快几个数量级,对应 MySQL 的 LOAD DATA INFILE / SELECT ... INTO OUTFILE。

同样的功能有两个版本,一句话区分:

命令 谁执行 文件在哪 权限要求
COPY 数据库服务端 服务器(容器)上的路径 需要超级用户或 pg_read_server_files / pg_write_server_files
\copy psql 客户端 执行 psql 的机器上的路径 普通用户即可

✅ 日常推荐用 \copy:不用超级用户,更安全,和 MySQL 的使用习惯最接近。

⚠️ 因为本文的 psql 是 docker exec 进容器执行的,所以 \copy 的文件实际也落在容器里,来回都需要 docker cp(见下面示例)。
